# 喵喵机 P2 HD 协议（A5）

P2 HD 使用一套完全不同的协议，帧头是 `0xA5`、帧尾是 `0x5A`，内部再套一层
`[parent, child, type, len, data]` 的命令结构。本文档来自对官方 App
`cn.paperang.mm` 的静态分析与实机验证。

> 验证环境：Windows 11、喵喵机 P2 HD（YC3122 蓝牙芯片、固件 1.0.0）。
> 设备信息：300 DPI、576 点、57 mm 纸、固件 1.0.0。

## 1. 传输层

- **经典蓝牙 SPP**（RFCOMM），Windows 配对后为 `蓝牙链接上的标准串行 (COMx)`
- 手机端抓到的链路是 `BT_TRANSPORT_BR_EDR`，且 `is_encrypted = true`
- 实测：**未加密的 BLE 链路上打印命令会被拒绝**（查询正常，返回码 3），
  所以必须使用经典蓝牙配对后的链路

P2 HD 同时广播 BLE 和经典蓝牙，Windows 会列出两个同名设备，属正常现象。

## 2. 帧格式

```
A5 01 | len(2 LE) | content | CRC32(4 LE) | 5A
```

- `len` 为 content 的字节数
- CRC32 参数与 P2 相同：标准 CRC-32，**初始值 `0x35769521`**，只算 content
- content 结构：

```
parent(1) | child(1) | type(1) | dataLen(2 LE) | data
```

`type`：`1` = 请求，`2` = 响应，`3` = 广播/最终包。

示例（走纸 50 行）：

```
content = 05 16 01 02 00 32 00
frame   = A5 01 07 00 05 16 01 02 00 32 00 <CRC> 5A
```

设备响应：

```
A5 01 08 00 | 05 16 02 03 00 01 00 00 | <CRC> 5A
                └ parent=5 child=22 type=2 len=3
                   data = 01 00 00   → 第一个字节 1 = 成功
```

**响应码**：`1` = 成功，`2` = 错误，`3` = 无效/不支持。

## 3. 命令表（parent = 5，热敏打印机）

| child | 方向 | 含义 | 数据 |
|-------|------|------|------|
| 22 | → | 走纸 | 行数 u16 LE |
| 23 | → | 打印自检页 | 无 |
| 25 | → | 打印开始 | 无 |
| 26 | → | 打印结束 | 无 |
| 27 | → | 打印数据 | 见下节 |
| 1  | → | 查询设备信息 | 无（返回 JSON） |
| 2  | → | 查询支持尺寸 | 无 |
| 4  | → | 查询 DPI | 无 |
| 5  | → | 查询加热点数 | 无 |
| 6  | → | 查询颜色支持 | 无 |
| 10 | → | 查询温度 | 无 |
| 16 | → | 查询浓度 | 无 |
| 20 | → | 查询打印速度 | 无 |

另有若干标签机/单词卡相关命令（NFC、纸类型、学习卡等），未在本项目中验证。

## 4. 打印数据（child = 27）

content 结构：

```
[seq u16] [contentLen u16] [precision u8] [width u16] [offset u16] [0] [chunkLen u16] [chunk]
```

| 字段 | 说明 |
|------|------|
| seq | 包序号，从 1 开始 |
| contentLen | 后续内容的字节数（= 8 + chunkLen） |
| precision | 1 = 黑白，4 = 4bpp 灰阶，2 = 2bpp |
| width | 每行字节数 = 打印宽度 / 每点字节数 |
| offset | 起始偏移，普通情况为 0 |
| chunkLen | 本包数据字节数 |
| chunk | 位图数据 |

### 黑白模式

- `precision = 1`
- `width = 576 / 8 = 72`
- 数据格式与 P2 相同：1bpp、MSB 在前、1 = 黑

### 灰阶模式

设备能力字段 `TPColorSupport = [0,0,0,0,1,12,0]`，其中的 `12` 对应
App 的 `PrintModeGrayRank12`：

| 模式 | 每点字节数 | precision | width |
|------|-----------|-----------|-------|
| 普通 1bpp | 8 | 1 | 72 |
| GrayRank16 | 2 | 4 | 288 |
| **GrayRank12** | **2** | **4** | **288** |
| GrayRank8 | 2 | 4 | 288 |
| GrayRank4 | 4 | 2 | 144 |

灰阶数据为 **4bpp**：每字节两个像素，高 nibble 为左侧像素。

```
byte = (left_level << 4) | right_level
```

等级范围取决于 Rank：Rank12 使用 0–11。

## 5. 设备信息（child = 1）

返回内容第一个字节是响应码，随后是 `len(2 LE)` 和 JSON 文本：

```json
{"TPInfo": {
  "TPSupportSize": 57,
  "TPDevDPI": 300,
  "TPHotSpotNum": 576,
  "TPColorSupport": [0, 0, 0, 0, 1, 12, 0],
  "TPNfcTagSupport": 0,
  "TPLabelPrinter": 0
}}
```

- `TPSupportSize`：纸宽（mm）
- `TPDevDPI`：打印分辨率
- `TPHotSpotNum`：加热点数（= 每行像素数）
- `TPColorSupport`：颜色/灰阶能力

## 6. 典型打印流程

```
5/25  打印开始
5/27  数据包 × N
5/26  打印结束
5/22  走纸若干行（把图送出机壳）
```

走纸是独立命令，打印结束后**不会自动出纸**。实测这台机器需要再走约
10 行才能看到打印内容的底边（这是打印头到出纸口的机械距离，与步进单位无关）。

## 7. 浓度

- 设置：`5/17`，1 字节，取值 **55 / 75 / 95**
- 查询：`5/16`

官方 App 只有三档，并把它们映射为 55 / 75 / 95；实测其它值不会产生
可见的连续变化，因此本工具只提供三档。

## 8. 注意事项

- 打印命令在未加密链路上会被拒绝（响应码 3），必须走经典蓝牙配对链路。
- 大量实心黑会显著增加电流，可能出现走纸打滑、电机异响。
- 不同批次可能换用不同蓝牙芯片/固件，协议行为需要以实测为准。
